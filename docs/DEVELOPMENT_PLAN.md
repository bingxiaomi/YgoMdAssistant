# 开发与验收记录

依据 [指导 v0.1](指导v0.1.md)，2026-10-19 完成 Phase 0 + Phase 1，并按后续要求将默认实时后端升级为 HWND 原生 WGC 捕捉。使用真实 MD 回放验证后台/遮挡原生分辨率采集、最小化等待及还原自动恢复。最新结果见 [原生捕捉验收](WINDOW_CAPTURE.md)，初版 DXcam 记录保留在 [历史验收](PHASE_0_1_VERIFICATION.md)。

## 已完成

- Phase 0：Python 包、配置校验、轮转日志、PySide6 桌面窗口、公共 Frame / DuelEvent / DuelState 数据契约、测试框架、Git 初始化及完整环境版本锁。
- Phase 1：游戏窗口枚举和选择、HWND 原生 WGC 捕捉（DXcam 可显式选用）、OpenCV 录像读取、共用后台帧管线、有界队列、毫秒及原始系统时间戳、手动 ROI 校准、比例坐标存取、两个 ROI 裁剪预览和原始帧调试工具。
- 录像交互：导入后暂停、播放/暂停、前后逐帧、时间轴跳转、结束后重新播放。
- 双击 `start.cmd` 可启动，`run.py` 不依赖工作目录。

当前环境：Windows x64 / Python 3.12.14；包支持范围扩展为 3.11–3.12，3.11 尚未单独实测。项目已成功 editable 安装，完整依赖锁为 `requirements.lock`。Git 远程关联 `https://github.com/bingxiaomi/YgoMdAssistant.git`，阶段进度保存在 `main` 分支；真实录像、截图和本地环境不纳入版本管理。

## 下一阶段

已补充一次整场真实回放的保存链路实测，见 [回放实测报告](REPLAY_TRIAL_20261019.md)。录像完整解码、原生分辨率及 PNG/ROI 像素一致性通过；发现日志对效果框的游戏内遮挡、无文字 ROI、存储开销和源采集频率不足 30 FPS，作为后续数据质量与性能工作的依据。

1. Phase 2：对已校准 ROI 接入 OCR，保存原始文字、置信度、帧及时间戳证据。
2. 增量日志拼接与相同动作不同实例的去重测试。
3. 当前效果描述与左侧卡片详情识别，建立固定录像识别质量报告。
4. 随后推进事件融合和状态重建；人工审核、JSONL 导出按指导文档的实施顺序接入。
5. 之后接入卡牌库、规则验证、Combo 搜索与本地模型。

本轮验证的是采集、ROI 和录像交互，尚不涉及文字识别准确率。短时真实回放测试不代表长期稳定性或全配置兼容性。
