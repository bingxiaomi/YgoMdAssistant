## 保存与回读结果

| 项目 | 实测 |
| --- | --- |
| 捕捉原生尺寸 | 2048×1152，源帧记录全程一致 |
| 录制耗时 | 422.844 秒，约 7 分 3 秒，含开场菜单与加载 |
| MP4 时长 | 422.733 秒，与录制耗时相差约 0.11 秒 |
| MP4 格式 | 2048×1152，15 FPS，6,341 帧 |
| 完整解码检查 | 6,341 / 6,341 帧成功，解码帧尺寸全部正确 |
| 源帧索引记录 | 8,856 条，ID 唯一、递增，系统源时间戳严格递增 |
| 源帧间隔 | 中位数约 48.61 ms，P95 约 48.63 ms，最大约 180.56 ms |
| 无损原图采样 | 每约 5 秒一组，共 85 组原始 PNG + 两个 ROI + 元数据 |
| 高频 ROI 采样 | 每约 0.5 秒一对，共 818 对，即 1,636 张 ROI PNG |
| ROI 像素校验 | 85 / 85 组与对应原图按保存配置裁剪的像素完全一致 |
| 预览视频重复帧 | 123 帧，约 1.94%，已在逐视频帧索引标记 `repeated` |
| MP4 文件大小 | 921,752,760 字节，约 879 MiB |
| 全部实测素材 | 约 1.75 GB（报告生成时统计），含原图、ROI、录像和索引 |

录像按实际时间写成 15 FPS 的预览文件；源帧到达不均匀时，预览中会明确记录补齐的重复帧。无损 PNG 和源帧索引不将补齐帧伪装为新的采集数据。索引记录不等于保存了 8,856 张原始 PNG，完整原图只按上述间隔采样。

MP4 使用有损编码。抽查 8 个具有相同源帧 ID 的 PNG / 视频帧对，PSNR 约 31.1–33.5 dB，因此后续识别或高质量标注应优先使用无损 PNG。此数值用于检查编码损失，不代表 OCR 准确率。

## 目视检查与发现

1. **原生图像清晰。** 效果文字完整样本为 940×112，能清楚阅读各分支描述。日志样本为 348×886，回合/阶段、卡名、动作和图标均可辨认。字形清晰度不受助手预览窗口大小影响。
2. **效果区域可能没有文字。** 平时保留的是场地背景；召唤动画或没有效果描述时，也不能把该 ROI 直接视为文字样本。
3. **游戏 UI 会产生遮挡。** 右侧日志打开时，会与右上方效果描述的右半部重叠，样本 `000580_effect_text.png` 可见两层文字。WGC 正确记录了游戏窗口表面，不能恢复已经被游戏自己遮住的文字。后续应标记可见性/遮挡，或采用分时采样：日志打开时保存日志，日志关闭时保存完整效果描述。
4. **日志面板内存在自然截断。** 滚动中的顶部日志可能仅显示半行，长卡名或文本也可能被游戏面板边界截断；ROI 已覆盖面板，不能仅靠扩大裁剪恢复游戏未显示的部分。
5. **当前保存开销较大。** 一场实测约 1.75 GB；保存全量训练素材前，需要确定无损关键帧保留频率、ROI 变化触发及预览视频编码策略。
6. **配置 30 FPS 不代表已稳定采到 30 FPS。** 本轮实际源记录平均约 20.9 FPS，存图期间最大源间隔约 181 ms。当前验证了保存链路与图像质量，尚未完成持续满 30 FPS 的性能验收。

结论：完整回放的捕捉、原生分辨率保存、ROI 保存、时间索引和视频回读可用。当前素材可用于后续 OCR 测试及人工审核；在进入训练集前，需要排除菜单、加载、无文字、动画遮挡和游戏 UI 叠挡等片段。本轮未执行 OCR，也未测量文本识别准确率。

## 复现工具

`tools/record_replay_trial.py` 保存预览录像、无损采样、ROI 和索引。`--end-reference` 指向已确认的 FINISHED 原生截图，用结束横幅的图像匹配作为本次调试停止条件；该条件是回放实测辅助逻辑，不是正式事件识别模块。默认最多录制 900 秒，也可在输出目录创建 `STOP` 文件结束。
