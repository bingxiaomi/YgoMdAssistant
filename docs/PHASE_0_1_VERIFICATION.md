## 已知限制

- DXcam 读取可见屏幕像素。测试明确观察到：IDE 覆盖游戏时，截图会包含 IDE。此情况不算 MD 成功样本。请并排摆放或使用第二显示器；本阶段尚无后台 HWND 画面采集。
- 最小化、关闭、客户区跨屏或部分超出屏幕时显示错误并停止，用户还原/调整后重新启动；不会把旧画面标为正在更新。
- 单显示器内移动/尺寸变化可跟随。多 GPU、跨显示器切换、竖屏、HDR、独占全屏尚未逐项实测。
- DXcam 的 HWND→输出映射使用固定 0.3.0 的内部发现元数据，隔离在适配器中；升级依赖须重新测试映射与释放。
- 不同比例、UI 缩放、带编码黑边的视频需独立校准并另存布局；参考分辨率仅作记录，ROI 始终按原始整帧比例缩放。
- 视频解码依赖 OpenCV 可用编码器；跳转精度和时间戳取决于文件及解码后端，优先 PTS，缺失时按帧率回退。
- 未实现 OCR、识别质量报告、事件时间轴、战术建议、规则或模型。当前验收结论仅覆盖 Phase 0 + Phase 1。

素材保留在本地 `data/captures/`，已被 Git 忽略。`tools/verify_md_workbench.py --layout` 可复现鼠标校准和切源验证，会调整窗口并写入 ROI 配置；正常使用只需打开 `start.cmd`。
